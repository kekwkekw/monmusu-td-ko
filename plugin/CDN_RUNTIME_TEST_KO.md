# MonmusuMod 0.4.0 CDN 로더 검증

2026-11-11 지정 DMM 실행 스크립트로 IL2CPP 게임에서 실기 검증했다. 아래 시간은 플러그인의 CDN 준비 구간이다. 로그 파일 해시와 DLL 식별값은 [검증 기록 JSON](CDN_RUNTIME_TEST_20261111.json)에 있다. 원본 로그와 덤프는 작업 환경에 보관했다.

| 조건 | 결과 |
| --- | --- |
| 4,146장면 공개 manifest 최초 실행 | CDN 준비 765ms. 시작 요청은 manifest와 Names 두 건. 시작 시 Novel 파일 읽기·요청 0건. |
| 필요한 장면 최초 진입 | 메인 `1101011Nml` 한 파일 요청, 117행 적용. 도감 도입부와 함께 컴파일되는 후속 장면은 두 파일 요청, 각각 26행과 44행 적용. 원문 불일치 0건. |
| CDN 연결 실패 | HTTP 제한 시간 후 검증된 공개 캐시를 사용해 시작. |
| 장면 응답 지연 | 시험 manifest에 등록된 장면 요청이 취소된 뒤 원문으로 진행. 다른 해시의 장면 캐시는 사용하지 않았다. 같은 세션에서 원문 저장·복원과 백로그 확인. |
| 최종 DLL로 메인 저장 복원 | native Utage API로 페이지 1 저장 → 3 진행 → 1 복원 → 2 진행. 두 차례 강제 GC 뒤 한국어 화자·본문·백로그 확인. 추가 Novel 요청 0건. |
| 진단 DLL 제거 후 재시작 | CDN 준비 186ms, manifest 요청 1건, 시작 Novel 읽기·요청 0건. 도감의 26행과 44행을 디스크 캐시에서 적용했다. 스킵과 복귀 후 같은 장면에 다시 진입하자 이미 적용된 26행과 44행을 재사용했다. 원문 불일치와 추가 다운로드 0건. |

최종 실행에서 기존 UI와 master 치환, 로컬 이미지 하단 메뉴 표시도 확인했다. 게임을 종료하고 임시 진단 DLL과 시험 CDN 설정·캐시를 정리했다. 당시 XUnity는 비활성이었다.

최초 후보에 진단 후크 38개를 켠 세션에서 도감 스킵 중 `0xc0000005` 접근 위반이 한 차례 발생했다. 설치된 IL2CPP 문자열 배열 인덱서는 GC write barrier 없이 포인터를 썼다. 최종 DLL은 native `Array.SetValue`를 사용한다. 최초 종료의 직접 원인은 미확정이며, 최종 DLL의 강제 GC 및 진단 없는 스킵·재진입에서는 재현되지 않았다.

Core 29개 검사에서 4,146장면의 번역 159,817행, 승인 HOLD 17행의 원문 유지, Names 776건을 대조했다. 공개 CDN 실기는 기존 manifest로 수행했고 `grid_names`가 포함된 전체 manifest는 로컬 패키지 검사와 격리된 지연 시험에서 사용했다. 실제 게임 표시는 표본 장면에서 확인했다. HOLD 장면 화면, 음성 청취, 일반 저장 UI, 다른 장면 또는 새 프로세스에서의 저장 복원은 미검증이다.
